# ashiato

Records which rows an app inserts, updates and deletes, using read-only (SELECT-only) database access.

## Hard rules
- Adapters must work with SELECT permission only: no triggers, no CDC, no temp tables, no setting changes. CDC / Flashback may only ever be optional extras.
- Everything runs locally; never send data anywhere. The server binds to 127.0.0.1.
- The MCP server's answers go to an AI (maybe in the cloud): row values, URL queries, the text of clicked elements other than buttons' captions and text fields' labels (the browser marks those: `ActionInfo.caption`), and the app's and database's error messages are left out unless it was started with `--share-values`; files it writes (tests, evidence, `verify_auto` reports) are returned as paths only. Without it, `pack` replaces the pages' text that may show values with `…` (cells, options, field values, links to records, headings of `:id` pages) and `verify_auto` returns `verifyText.ts`'s summary (failures' `valueFree` messages, `problemShape`, counts and columns).
- Database drivers (mssql, oracledb, pg, mysql2) are optional peer dependencies loaded with `loadDriver()`.
- `ashiato query` runs only statements that read: every statement of the files must pass `readOnlyProblem` (SELECT / WITH, no word that writes, locks or reaches outside, checked under every quoting the dialect may use) or none is run. Adapters run them as a second guard in a read-only transaction (PostgreSQL, MySQL, Oracle), a transaction always rolled back (SQL Server) or a read-only database (SQLite). Its results (row values) only go to the clipboard / a file: the person decides to paste them into a chat.

## Layout
- `packages/ashiato` — the npm package: `src/core` (snapshot, diff, recorder, media: replay/video files next to the session), `src/adapters` (one file per database), `src/server` (HTTP API + static UI), `src/cli` (`recording.ts`: recording + timeline server, shared by `record` and `mcp`), `src/agent` (for AI agents: dependency-free stdio MCP server, its tools, steps as text with or without values; `verifyText.ts`: `verify_auto`'s summary without values), `src/chat` (for AI chats without an agent: `ashiato schema` table definitions as Markdown, `ashiato query` statement splitting + read-only check in `sql.ts`, results as Markdown, clipboard through the OS's command, `ashiato verify`: `verifyFile.ts` reads the steps file a chat writes, `verify.ts` takes the person through the steps and compares each one's changes with `src/testing/match.ts`; end-to-end from a chat: `actions.ts` parses the steps' `操作:` / `Actions:` lines, `auto.ts` does them with Playwright for `verify --auto` (locators shared with the exported tests, failure diagnosis with and without values), `browser.ts` launches it, `aria.ts` reads / shapes / hides values in accessibility trees, `pack.ts` crawls the pages and writes `ashiato pack`, `exportTests.ts` writes `ashiato export-tests`, `files.ts` finds sessions and tests), `src/testing` (`expectDbChanges` matching (it also takes `verify.md` expected-changes lines) and the watcher that waits for changes to settle; `ChangeBy`, `OTHER_COLUMNS` and the `unlisted` option are for `verify` only, not exported from the package), `src/playwright` (Playwright fixtures, export `ashiato/playwright`), `src/codegen` (Playwright tests from a recording: page mirror rebuilt from the rrweb replay → user interactions → locators → test code), `src/export` (evidence export: dependency-free .xlsx writer, HTML printed to PDF and screenshots taken by a local headless Chrome / Edge over the DevTools pipe; `capture.ts` is the screenshot page's script, built as `dist/capture.global.js`), `src/vite` (Vite plugin, export `ashiato/vite`), `src/client` (browser script the plugin inlines: action tracker + fetch / XHR / WebView2 postMessage hooks + rrweb screen replay recording + custom replay events for codegen in `events.ts`: dialogs, Enter, options picked by a script; built as `dist/client.global.js`).
- `packages/ui` — React timeline UI (step list, diffs, rrweb replay, screen recording via getDisplayMedia), built into `packages/ashiato/dist/ui`.

## Commands
- `pnpm test` — unit + SQLite tests. Real servers run when `ASHIATO_TEST_{POSTGRES,MYSQL,MSSQL,ORACLE}_URL` is set (CI sets all four). The adapter test connects as a user granted only SELECT (Oracle also needs `ASHIATO_TEST_ORACLE_ADMIN_URL`), so permission-dependent catalog queries are covered. `test/oracle-thick.integration.test.ts` also needs `ASHIATO_TEST_ORACLE_LIB_DIR` (an Oracle Instant Client folder; on Linux also on `LD_LIBRARY_PATH`). The real-browser Vite test (`test/vite.e2e.test.ts`, also covers the timeline UI replay and screen recording) needs `pnpm build` first and a Chromium for playwright-core; CI sets `ASHIATO_REQUIRE_E2E=1` so it can't silently skip. `test/auto.e2e.test.ts` runs `verify --auto`, `pack`'s crawl and the MCP `pack` / `verify_auto` tools in a real browser (same Chromium, same `ASHIATO_REQUIRE_E2E`). `test/playwright.e2e.test.ts` runs the real Playwright test runner on the built `ashiato/playwright` (recorded and `export-tests` tests); `test/agent.test.ts` runs the built `ashiato mcp` over stdio.
- `pnpm typecheck`, `pnpm build`
- Release: bump `packages/ashiato/package.json` version, then the maintainer runs `pnpm release` at the repo root (= `pnpm publish` in `packages/ashiato`; npm passkey auth in the browser, so not the agent). `E404 Not Found - PUT` means the npm login session expired: `npm login`, then run it again (nothing was published). `prepublishOnly` runs typecheck → build (UI + package) → test, so a stale `dist/` can't be published. Check the result with `npm pack ashiato@<version>`.
